Noms de propriétés : ProducerName, ProducerCountry, ProductionPlace, Area

Le Système d'information de l'UE lit quatre propriétés facultatives sur chaque parcelle. Leurs noms sont sensibles à la casse et tout le reste est ignoré : « pays » ou « productionplace » ne transmettent donc rien.

English version

Ce que dit la documentation de l'UE

La page GeoJSON File Description liste les propriétés facultatives traitées par le système :

PropriétéSignification
ProducerNameNom facultatif du producteur pour la géométrie
ProducerCountryPays de production, en code ISO à 2 lettres
ProductionPlaceNom facultatif du lieu de production (recommandé)
AreaSurface en hectares, pour les géométries Point

Toute autre propriété valide sur le plan syntaxique est ignorée. La page cite parmi les erreurs courantes les « noms de propriétés invalides (par exemple casse incorrecte : 'productionplace' au lieu de 'ProductionPlace') » et les « codes pays ISO2 invalides ». Elle rappelle aussi que "Area": "3" entre guillemets est lu comme 0.

Fichiers de type I et de type II

L'UE décrit deux variantes de même structure. Un fichier de type I s'utilise via l'API et au niveau du producteur dans l'interface web. Un fichier de type II, importé au niveau de la marchandise dans l'interface web, contient plusieurs producteurs regroupés par ProducerName et ProducerCountry, et doit comporter ProducerCountry sur chaque entité. Le système recommande aussi de toujours indiquer ProductionPlace.

Erreurs fréquentes

  • Noms traduits ou locaux : pays, superficie, nom_producteur, country.
  • Mauvaise casse : producerCountry, PRODUCERNAME, area.
  • Noms de pays au lieu de codes : "Côte d'Ivoire", "Ghana", ou des codes à 3 lettres comme CIV. La valeur doit être le code à 2 lettres, par exemple CI, GH, CM, ET, BR.
  • Codes en minuscules : ci au lieu de CI.
  • Area en texte ou dans une autre unité : voir la règle des 4 ha.

Comment corriger

Renommez les colonnes de votre tableur source avec les noms exacts ci-dessus avant la conversion, ou renommez les champs dans QGIS (propriétés de la couche, Champs). Remplacez les noms de pays par les codes à 2 lettres. Ouvrez ensuite le GeoJSON dans un éditeur de texte et vérifiez une entité à l'œil.

Ce que fait le vérificateur

  • Alias reconnus et mauvaise casse (pays, superficie, producer_name, productionplace et d'autres) : avertissement, renommés avec les noms officiels dans le fichier corrigé.
  • ProducerCountry qui n'est pas un code à 2 lettres : erreur, converti en code ISO à 2 lettres quand le pays est reconnaissable.
  • ProducerCountry absent sur certaines parcelles seulement : avertissement.
  • Parcelle située hors de son pays ProducerCountry : avertissement, qui révèle souvent des coordonnées inversées.

Une entité minimale correcte

{"type":"Feature",
 "properties":{"ProducerName":"Coop Exemple","ProducerCountry":"CI",
               "ProductionPlace":"Parcelle 12","Area":2.5},
 "geometry":{"type":"Point","coordinates":[-4.012345,5.312345]}}

Cet exemple est fictif. Notez la casse exacte de chaque nom, le code pays à 2 lettres, le nombre sans guillemets pour Area et la longitude avant la latitude. Les autres propriétés peuvent rester dans vos propres archives : le système les ignore, elles ne font qu'alourdir le fichier.
